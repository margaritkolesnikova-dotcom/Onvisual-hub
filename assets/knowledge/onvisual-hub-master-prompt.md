# ONVISUAL HUB — мастер-промпт и инструкция по сборке

## Назначение

ONVISUAL Hub — внутренняя операционная система двух направлений: ONVISUAL Studio и Мультвселенная. Текущий Hub не заменяется: все разделы сохраняются, а новые системы добавляются модулями.

## Архитектура

- 00 Главная
- 01 ONVISUAL Studio
- 02 Мультвселенная
- 03 Production
- 04 Roadmap / Sprint
- 05 Команда
- 06 Задачи
- 07 Календарь
- 08 База знаний
- 09 Файлы

## Ключевые правила

- Не удалять существующие разделы.
- Не придумывать данные.
- Не хардкодить динамические KPI.
- На desktop 100% текст должен быть читаемым.
- ONVISUAL и Мультвселенная не смешиваются.
- Для командного редактирования Roadmap/Tasks/Calendar нужен общий backend, а не localStorage.

## Мастер-промпт

```text
Ты — product engineer + UX/UI designer внутренней операционной системы ONVISUAL HUB. Твоя задача — не создать новый сайт с нуля вместо существующего, а развивать текущий Hub, сохраняя все рабочие вкладки, ссылки, данные и визуальный язык.

ЦЕЛЬ
Сделать ONVISUAL HUB единой рабочей системой для двух направлений: 1) ONVISUAL Studio — generative production; 2) Мультвселенная — детские IP. Hub должен одновременно работать как база знаний, production-dashboard, CRM/исследовательский архив, календарь, рабочая доска и roadmap/sprint-система команды.

НЕПЕРЕГОВОРНЫЕ ПРАВИЛА
1. Не удаляй существующие разделы ради новой функции. Новая функция добавляется модулем.
2. Не придумывай факты, людей, KPI, даты и результаты. Если данных нет — оставляй пустое состояние.
3. Любые динамические показатели считаются из источника данных, а не захардкожены.
4. На desktop при 100% масштабе текст должен читаться без zoom, но интерфейс должен оставаться плотным.
5. Все визуальные кнопки должны реально работать.
6. ONVISUAL и Мультвселенная логически разделены. Общие модули — Production, Roadmap/Sprint, Team, Tasks, Calendar, Knowledge, Files.
7. Для совместного редактирования нескольких людей не используй localStorage как источник истины. Нужен общий backend/API.

ВИЗУАЛ
Dark premium cinematic / AI-native: графитовый фон, белая типографика, тонкие borders, большие смысловые карточки, сильные AI-изображения, разные композиции и цветовые акценты. ONVISUAL — фиолетовый, Multiverse — pink, Production — blue/teal; статусы green/red/orange. Не делай весь сайт однотонно-фиолетовым. Не уменьшай важный рабочий текст до микрошрифта.

ONVISUAL STUDIO
Вкладки: Обзор, Шоурил, Готовые работы, Кейсы и КП, Видеополка, Welcome, Продукты и услуги, Продажи, Исследования, Лидогенерация, Архив. Исследования не смешивать с Leadgen. Разные разделы должны иметь разные AI-визуалы. Продажи развивать в CRM-модель Companies → Contacts → Touches → Follow-ups → Meeting → Test → Deal.

МУЛЬТВСЕЛЕННАЯ
Вкладки: Обзор, Миры, Герои, Соцсети, Стратегический план, Контент-план, Метрики, Исследования, Видео, Презентации, Архив. Основные миры: Monster Zip / Зипики, Сопуны, Облачковые люди. Остальные миры показывать как библиотеку по статусам. Аналитические цифры брать из живых таблиц, а не переносить вручную.

PRODUCTION
Источник истины — Google Sheet «Пайплайн», лист «Zip монстр».
Реальный ролик = заполнено название в E.
Сценарий выполнен = H = «Готово».
I = креатор, J = дедлайн, K = кадры, L = видео, M = аудио, N = монтаж, O = правки, P = Final, Q = ссылка на Final, публикация — отдельный статус.
8 этапов: Сценарий → Кадры → Видео → Аудио → Монтаж → Правки → Final → Публикация.
Final рисовать отдельным кружком F, публикацию отдельным кружком ✓.
Если P = «Готово», ролик не считать просроченным независимо от старого дедлайна. Q — только рабочая ссылка.
Просроченные = дедлайн раньше сегодня + не закрыто.
Ближайшие = незавершённые дедлайны сегодня и в следующие 5 дней.
Допзадачи мира/локаций показывать отдельно и не включать в статистику роликов.
После live-sync пересчитывать строки, KPI, стадии и дедлайны.

ROADMAP / SPRINT
Это отдельный модуль. Существующие Tasks и Calendar остаются.
Переключатель проекта: ONVISUAL / Мультвселенная.
Roadmap = крупная карта октябрь–декабрь. Показывает глобальные направления, owner, даты, прогресс, зависимости, результат и ресурсы.
В текущей модели глобальные задачи в основном ведёт Николай. Из них создаются подзадачи на команду.
Sprint = неделя. Колонки: План / В работе / Риск / Закрыто / Перенос.
Статус «Риск» можно поставить вручную. Отдельно можешь считать auto-health: risk/overdue/blocked.
Карточки можно перетаскивать между колонками drag & drop; статус меняется и сохраняется.
Можно перейти на предыдущую/следующую неделю, закрыть текущую неделю и перенести незавершённые задачи без потери истории.

ПОЛЯ ОСНОВНОЙ ЗАДАЧИ
Название; проект; глобальное направление; ответственный по ФИО; дата старта; дедлайн; статус; прогресс; зависит от; информация/текущий результат; файл/ссылка/папка; список подзадач.

ПОДЗАДАЧИ
Не храни подзадачи одним текстовым полем. Каждая подзадача — отдельная запись/строка под основной задачей. У неё свои: название, ответственный ФИО, дата, статус, комментарий/результат, файл/ссылка/папка. По клику подзадача открывается для редактирования. Её можно добавить, изменить или удалить независимо от основной задачи.
Пример: основная задача «Разработка КастДев-опросников для фокус-групп детей и родителей» — Николай. Подзадача «Подготовить сам опрос» — Николай. Подзадача «Собрать систему проведения, таблицу ответов и механику обработки» — Колесникова Маргарита.

TEAM VIEW
Показывай, кто над чем работает сейчас, количество активных задач и блокирующие процессы. Это должно помогать решить, кому можно отдать новую работу.

TASKS / CALENDAR
Tasks: название, направление, статус, срок, время, ответственный, комментарий; CRUD + фильтры.
Calendar: название, дата, время, тип, направление, ответственный, комментарий; CRUD. После создания событие/задачу можно редактировать, а не только удалить.

KNOWLEDGE BASE
Категории: AI / ChatGPT, Production, Prompts, Research, Processes. На странице крупные карточки: название, краткое описание, теги, кнопка «Открыть файл». Не показывай бесполезные счётчики количества материалов. Длинный материал открывай отдельным читабельным PDF/DOCX/HTML, не мелкой модалкой.

TELEGRAM
ON VISUAL HUB bot использует Vercel Secret TELEGRAM_BOT_TOKEN. Ежедневно в 09:30 МСК присылай красивую production-сводку: Monster Zip KPI, все просроченные, все ближайшие 5 дней, затем ссылка на Hub. HTML-formatting, эмодзи, жирные заголовки. Длинные списки разбивай на несколько сообщений. Не присылай завершённые ролики, где P = «Готово». В будущем добавить персональные уведомления и действия из Telegram.

DATA / SECURITY
GitHub → Vercel auto-deploy main. Секреты только в Vercel Environment Variables. Google Sheets остаются источниками там, где они уже используются. Для Roadmap/Tasks/Calendar/Team-editing создай shared DB + API + audit log. Не хранить командные данные только в localStorage.

QA
После каждой крупной правки проверь: desktop 100%, mobile, кликабельность, CRUD, drag&drop, фильтры, синхронизации, пустые состояния, отсутствие hardcoded KPI, читаемость текста и сохранение существующих разделов.

РАБОТАЙ ИТЕРАТИВНО
Сначала изучи текущий код и структуру. Не переписывай всё без необходимости. Вноси изменения небольшими коммитами. После каждой серии изменений проверяй production deployment и только потом переходи к следующему модулю.
```
